# 场景迁移与优化：六步指南

把场景交给 Agent，把效果确认留给你。

美术人员负责准备素材、说明要求、看图确认；Agent 负责检查、处理、出图和交付。先完成 Blender 迁移优化，经您确认后，再通过 Unity Skills 导入指定 Unity 工程进行测试。

这是协作指南，不是自动转换面板。网页一次只显示一步，不会上传文件、连接软件或替您批准任务；切换步骤和复制文字都不代表实际执行、效果通过或操作授权。

## 01 准备素材

一次交齐，减少来回沟通。

### 您要做什么

- 提供 .max 和完整贴图文件夹，有原效果图也一起提供。
- 说明最终用于电脑、手机还是头显，以及是否需要近看或进入内部。
- 列出不能改变的细节，并提供目标 Unity 工程名称和位置；不清楚的内容请 Agent 检查。

### Agent会做什么

- 列出收到的素材、还缺什么，以及需要您确认的处理范围。
- 了解目标设备与效果要求，此时不连接 Unity。

### 怎样算完成

- 输入、目标和重要细节明确；资料缺失已列出，未把猜测当成事实。

### 不通过怎么办

补齐缺少的素材，或明确接受某项替代方案；没有原效果图时，不宣称与原场景完全一致。

### 复制给Agent

> 请阅读《场景迁移与优化-六步指南》和本项目 AGENTS.md。我提供了 .max、配套素材和用途要求。请先检查资料，列出缺少的内容并给我处理方案。不要覆盖原文件、安装软件或提前连接 Unity。请用美术人员能理解的话说明问题。

## 02 检查与备份

先保护原件，再开始处理。

### 您要做什么

- 确认 Agent 提出的方案和允许调整的范围。
- 缺少软件、插件或使用权限时，按说明协助准备；不需要自己写代码。

### Agent会做什么

- 检查软件与素材能否安全读取，在独立工作副本中处理，原件不覆盖。
- 列清缺贴图、打不开的材质和异常模型，未获确认不自行替换。

### 怎样算完成

- 原件已保留，副本可用；缺失项已解决或具体处理方式获您同意。

### 不通过怎么办

暂停并说明缺少什么；不关闭安全保护、不擅自购买或安装、不反复重跑失败操作。

### 复制给Agent

> 我同意你刚才列出的方案和处理范围。请保留原件、建立独立副本，只执行已确认的 Blender 迁移与优化；出现新的缺失项或需要改变外观时先告诉我。不要连接 Unity。

## 03 Blender迁移优化

先还原，再减负，始终保留对照。

### 您要做什么

- 查看原效果与迁移结果对比，指出重要人物、文字和近景细节。
- 若希望改变颜色或整体风格，另行明确提出；默认保持原外观。

### Agent会做什么

- 先保留未优化的 Blender 版本，修复迁移中的缺失、错位和材质问题。
- 再在新版本中优化材质、减少不必要的面数、处理贴图并整理名称。
- 先做小范围对比，再扩大处理；不对全场统一减面，不随意合并所有零件。

### 怎样算完成

- 提供未优化版本、优化版本，以及同角度的全景、内部和重要近景对比图。

### 不通过怎么办

返回保留版本调整。文件变小不等于画面更好，也不等于目标设备运行更流畅。

### 复制给Agent

> 请先核对未优化版本，再进行材质优化、减面和名称整理。保留人物、文字和重要轮廓，不改变整体风格，不覆盖母版。请提供同角度的全景、内部和重要近景对比，单独标出已知差异。

## 04 确认Blender效果

第一个确认点：看清楚，再进入 Unity。

### 您要做什么

- 看模型有无缺失、错位和变形；看贴图是否清晰，玻璃和金属是否正常。
- 确认内部、背面及实际观看距离下的效果，指出不接受的差异。
- 明确确认某个版本，并说明是否允许进入指定 Unity 工程测试。

### Agent会做什么

- 记录您认可的版本和截图，保存后重新打开 Blender 工程核对。
- 导出目标模型，再在空场景重新打开检查；外观有变化时重新请您确认。

### 怎样算完成

- 指定 Blender 版本获您确认，Unity 阶段获授权，导出文件重新打开检查正常。三个条件缺一不可。

### 不通过怎么办

截图圈出问题，返回第03步。仅说画面通过，不等于允许连接 Unity；切换网页步骤也不是授权。

### 复制给Agent

> 我确认 Blender 的【版本名称】效果通过，接受已列明的差异。请先完成导出与重新打开检查，正常后仅通过 Unity Skills 连接【工程名称和位置】，导入独立目录并新建测试场景。不要覆盖旧模型或修改正式场景。括号内容由我确认后填写。

### 修改意见模板

> Blender 的【版本名称】暂不通过。问题在【截图和位置】，我希望【具体效果】。请在副本中调整并重新提供同角度对比，不进入 Unity。请先等我补齐括号内容，不要自行猜测问题或认可版本。

## 05 Unity导入测试

连接正确的工程，在独立场景里看效果。

### 您要做什么

- 打开指定 Unity 工程，保存正在编辑的内容，并开启 Unity Skills。
- 需要时提供 Unity Skills 面板的连接信息或截图；软件或技能缺失时请 Agent 说明准备方式。

### Agent会做什么

- 只通过 Unity Skills 连接，核对实际工程名称、位置和操作权限。
- 导入新目录，新建测试场景；不修改业务场景或覆盖旧资源。
- 检查大小、位置、全部材质和同角度画面，再检查目标环境下的运行情况。

### 怎样算完成

- 目标工程正确，测试场景可打开，提供 Unity 对比图、已知差异及未测试项。

### 不通过怎么办

连接错误或权限不足就暂停，不改用其他方式。Unity 内问题修复后重测；需修改模型或材质则返回第03步，并重新经过第04步确认。

### 复制给Agent

> Blender 认可版本和 Unity 测试授权已经明确，目标工程已打开。请通过 Unity Skills 核对工程后，在独立目录和新测试场景中验证。请展示与认可版本对应的视角；连接、权限或工程身份异常时停止，不绕过 Unity Skills。

## 06 确认与交付

第二个确认点：效果通过，文件也要完整。

### 您要做什么

- 检查尺寸、位置、人物文字、玻璃金属，有无粉色、全黑、透明异常或贴图丢失。
- 确认 Unity 指定版本的画面，以及接受哪些差异；运行性能与画面分开判断。

### Agent会做什么

- 保存并重新打开测试场景，检查层级、材质和资源仍完整。
- 整理可编辑工程、导出模型、测试场景及配套资源、对比图和恢复说明。
- 列明目标设备是否实际测试；没有测试就明确写“未测试”。

### 怎样算完成

- Unity 指定版本获您确认，保存重开正常，交付文件齐全；未完成项与接受的例外清楚。

### 不通过怎么办

Unity 画面或重开检查异常返回第05步；需改 Blender 则返回第03步并重新确认。测试通过不自动授权替换正式场景。

### 复制给Agent

> 我确认 Unity 测试场景的【版本名称】画面通过。请保存并重新打开检查，整理完整文件、对比图、已知差异和未测试设备。发现变化先修复并重新给我确认；本次不授权替换正式场景里的旧模型。

### 修改意见模板

> Unity 测试场景的【版本名称】暂不通过。问题在【截图和位置】，表现为【现象】，我希望【具体效果】。请先定位原因；若需修改 Blender 模型或材质，返回第03步并重新经过第04步确认。不要修改正式场景，括号内容由我补齐。

## 最终会拿到什么

- 未优化 Blender 版本：用于对照和恢复。
- 已确认的 Blender 优化工程：用于继续编辑。
- 经过检查的导出模型：用于导入。
- Unity 测试场景及其配套资源：说明所在工程和打开方式，不只给缺资源的场景文件。
- 同角度对比图、已知差异、未测试项和恢复说明。

## 常见问题

### 只有一个.max文件可以开始吗

可以先检查。但场景可能缺少贴图或插件；缺什么先列出来，不承诺仅凭这个文件就能完整还原。

### 点击下一步就会自动开始吗

不会。上一步、下一步和顶部导航只切换阅读内容；复制按钮只复制话术。页面不保存完成进度、不发送给 Agent，也不读取项目状态；请先补齐话术中的版本等信息，再自行发送给 Agent。

### 我需要会编程吗

不需要。把对应步骤的话术和素材发给 Agent，您负责明确效果要求和看图确认；技术配置由 Agent 处理。

### Unity Skills连接不上怎么办

暂停并核对工程、服务与权限。不得换工程或绕过 Unity Skills。当前工具包不附带该软件或技能的安装包。

## Agent执行底线

- 这份 Markdown 是六步内容依据，HTML 是同内容的阅读版。可独立阅读本文理解需求；执行前还要遵守项目 AGENTS.md，阅读现有 README、快速开始、脚本适用范围和相应模块说明。
- 当前通用自动入口只实现安全审计，不把完整流程描述成任意场景的一键转换能力；转换需根据素材与软件能力适配。
- 操作前核实源资产、资源目录、软件版本、目标设备、允许近似范围和质量预算。未知信息询问用户，不从其他案例推断授权。
- 保留源 .max、未优化母版、优化版和导出版；固定开启 Safe Scene，不覆盖原件、不修改用户正在编辑的实例。
- 没有用户对指定 Blender 版本的确认、Unity 阶段许可和导出检查通过，不连接 Unity。页面切步或复制操作、口头含糊评价或历史报告都不能替代这三个条件。
- Unity 阶段读取实际可用的 Unity Skills 说明，通过其连接发现与检查流程核对工程、操作模式、权限和未保存状态。参数和技能名以真实服务为准，受限时停下，不绕过服务、不手改场景文件规避限制。
- 只导入独立资源目录和新测试场景。不得擅自修复无关业务依赖、替换正式资产、安装插件、发布或清理旧文件。
- 确认记录关联版本、文件路径与SHA256、截图及用户确认内容。输入变化或模型材质修改后，重新验证受影响阶段；不要沿用旧截图。
- 视觉、结构、保存重开、目标设备性能分别报告。截图非空或脚本成功不能代替效果验收，未执行的项目写“未执行”。
- 出错时保留日志和产物，先查原因，不盲目重复运行。需要扩大修改范围时，重新取得用户确认。
