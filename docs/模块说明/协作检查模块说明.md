# 协作检查模块说明

## 职责与依赖

scripts/协作/检查提交范围.py从Git对象读取暂存树或提交树，单向复用受信任的分享工具及生成器验证内容，不执行候选脚本、YAML、模板中的JavaScript或模型文件。

scripts/协作/初始化协作环境.py只核对钩子和当前克隆配置。模板在.githooks；仓库允许清单为configs/仓库提交白名单.json。Git专用文件不进入给使用者的分享包，因此本模块实际执行需要完整克隆。

## 检查模式

- index：读取ls-files的暂存对象，拒绝冲突；使用已获取origin/main的白名单，不使用暂存区自行修改的名单；main不允许日常提交。
- push：读取Git传入的四字段引用行；检查新分支相对origin/main或已有分支相对远程旧提交的所有新增提交，拒绝非快进、main、标签与删除。
- range：显式base、head和policy-ref，用于受信任CI及测试。所有引用先解析为提交号，再读取对象。

错误退出码1，成功0。默认单文件2MiB，普通文件模式仅100644或100755；符号链接、子模块、非UTF8及NUL二进制拒绝。白名单路径禁止通配符和越界。有限敏感模式只报告规则和文件，不显示命中正文。

每个候选树还须保有合法仓库名单；分享清单指向的文件须存在，HTML与该树的Markdown及模板一致。允许名单登记尚未添加的未来文件，支持先审核名单、再提交内容的两阶段流程。

## 信任与限制

本地钩子不是不可绕过的安全机制，成员必须先安装并保持正常启用。仅本地origin/main可能落后于服务器，使用者应先获取；CI使用事件中的真实base进行复核。

repository-policy由pull_request_target触发时，只检出目标分支；候选只作为Git对象读取，不检出或运行。标准测试在另一只读pull_request任务执行，不接收仓库秘密。策略结果通过固定上下文repository-policy绑定候选SHA，避免仅把结果记到base。

代码所有者审核与保护main共同约束关键规则变化；它们不能阻止管理员修改设置，也不能保证任何形式的秘密都被扫描到。工作分支上已上传的信息可能已暴露，不能等合并检查再做首次隐私审查。

## 验证

测试提交检查.py使用临时Git仓库，覆盖暂存与工作文件差异、加白自放行、大小、敏感文本、删除、历史提交、main保护、链接与安装冲突。无网络推送、不修改用户全局Git配置；真实远程检查和分支保护需单独读回验证。

规范见 [多人协作与提交规范](../执行规范/多人协作与提交规范.md)。新增模块依赖是协作检查→通用分享检查，无反向依赖，不额外建立规则服务。
