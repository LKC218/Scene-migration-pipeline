# 环境与配置

## 不同运行时不要混装

| 用途 | 运行时与依赖 | 当前边界 |
|---|---|---|
| 配置、检查、预览、分享和离线测试 | 外部 Python 3.10+；仅标准库 | 无需 requirements.txt 或 pip 安装 |
| Max 内部审计 | 已安装 Max 自带 Python 与 pymxs | 不用 pip 安装 pymxs；由 Max Batch 启动 |
| Blender 迁移与回读 | Blender 自带 Python、bpy、mathutils | 本期通用入口不执行转换 |
| 历史图像和贴图脚本 | 视脚本使用 Pillow、NumPy、OpenCV | 不进入基础分享包，不承诺统一版本兼容 |
| 历史 glTF 官方验证 | Node.js 与 gltf-validator | 不进入基础分享包；使用前另行锁定依赖版本 |

本仓库不承诺所有Max、Blender与Python版本组合均兼容。使用者必须记录自己的版本，先做代表场景小样。工具检查不会运行版本探测或授权测试。

## 配置契约

文件：`configs/项目配置.local.json`，样例：`configs/项目配置.example.json`。所有字段必须存在，未知字段、重复键和错误类型均拒绝。

| 字段 | 类型 | 含义 |
|---|---|---|
| schema_version | 整数 | 固定为 1 |
| project_name | 字符串 | 任务标签，不用于自动拼接输出路径 |
| scene | 字符串 | 存在的 .max 文件；空值会阻塞 |
| max_batch | 字符串 | 存在的 3dsmaxbatch.exe；不从历史安装路径猜测 |
| blender | 字符串 | 可留空；非空时必须是存在的 blender.exe |
| output_dir | 字符串 | output/过程资产 下尚不存在的新批次 |
| protect | 字符串数组 | 额外需要保护的已存在目录；源文件父目录自动保护 |
| material_details | 布尔值 | 是否提取原材质参数与引用图 |
| plugin_environment | 对象 | 仅允许插件目录变量，覆盖本次子进程环境 |

插件变量只接受 `ADSK_APPLICATION_PLUGINS` 及 `VRAY_FOR_3DSMAX<版本数字>_MAIN`、`VRAY_FOR_3DSMAX<版本数字>_PLUGINS`。具体名称和值须根据实际安装验证，不自动生成。前者可用分号连接多个存在的目录。

通用入口的配置路径和字段中的相对路径始终相对于工具包根目录；不展开百分号变量或波浪号，请填写实际路径。底层历史脚本的路径规则可能不同，不应推断其行为。

## 检查层级

- `check`：只读验证字段、文件存在、平台及输出与保护范围。
- `plan`：附加展示实际调用参数，不创建批次。
- `audit`：默认与预览相同。
- `audit --execute`：检查无阻塞后才委托独立审计入口执行。
- 独立审计的非零退出码保留给调用者；工具配置错误返回 2。

源目录应仅包含本次所需资产，否则保护哈希扫描可能非常耗时。入口不自动冻结输入、不重链接纹理、不安装插件，也不终止超时进程。

## 常见问题

| 提示 | 处理 |
|---|---|
| 找不到本机配置 | 复制样例并填写，不要直接运行空白样例 |
| 输出已存在 | 核对是否仍有任务运行；保留记录并选择新批次 |
| 输出与保护目录重叠 | 将输入、已有交付与新批次分开 |
| 插件目录不存在 | 核对真实安装目录，不用虚假目录跳过检查 |
| 审计阻塞但生成了报告 | 阅读原日志和迁移前置检查，不把文件存在当成功 |
| 图片存在但材质仍异常 | 继续检查插件类、材质参数、UV 和目标导入器 |

`*.local.json`、日志、快照和审计报告可能包含个人路径与业务信息，默认不分享。敏感信息检测只覆盖部分常见模式，不能替代人工审核。
