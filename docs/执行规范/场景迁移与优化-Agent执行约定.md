# 场景迁移与优化：Agent执行约定

面向执行任务的 Agent；美术用户只需阅读 [美术操作流程](../使用指南/场景迁移与优化-美术操作流程.md)。本文件规定协作顺序，不代表已实现完整自动转换器。

简化入口是 [六步指南Markdown](../使用指南/场景迁移与优化-六步指南.md)，对应 [离线HTML](../使用指南/场景迁移与优化-六步指南.html)。HTML内所有步骤、话术和执行底线来自这份Markdown，但一次只显示一步，详细内容按需展开。网页不记录完成进度，切步和复制均不会传递给Agent，也不证明任务执行或用户授权。

## 角色和能力

- 用户提供素材、质量要求和两次视觉确认；不要把命令行、JSON或接口参数填写作为其默认工作。
- Agent负责调查环境、按批准范围准备配置、备份、处理与验证。技术问题转化为“影响什么、需要用户决定什么”。
- 基础审计可用当前通用入口；Blender迁移与优化仍按场景适配。
- Unity测试必须使用Unity Skills。目标工程需要对应服务，执行端需要对应技能；工具包不附带Unity Skills安装包，也不自动安装或升级。
- 无可用能力时标记阻塞并保留产物，不用截图、文件存在或历史案例冒充运行结果。

## 分阶段许可

1. 检查素材并提出方案，说明需要读取和写入的范围。
2. 用户批准后，在副本中执行Blender迁移和优化，不连接Unity。
3. 获得用户对指定Blender版本的确认，以及连接指定Unity工程、隔离导入与新建测试场景的许可。
4. 导出并独立回读通过后，才连接Unity Skills；确认工程身份和运行条件，再执行已批准的测试。
5. 获得Unity指定版本的视觉确认，保存重开并交付；不推导出业务替换许可。

如用户仅确认画面但未授权Unity阶段，应单独询问。用户要求修改几何或材质时，重新出图确认受影响版本。仅修正Unity场景照明等局部设置时，重做对应Unity验证；不能悄悄修改Blender已接受版本。

## 版本与证据

- 分开保存源资产、未优化Blender母版、优化版和目标导出版，不覆盖原件。
- 每个确认关联文件路径、SHA256、版本标签和对应截图，不能只记录“通过”。
- 图片标明相机或观察位置、版本和分辨率；重要部位单独近景，不以图像平均差异代替实际看图。
- 原效果基准不可用时，明确不做与原效果一致的结论。
- 命名保持唯一、可读，并保留旧名映射；语义未知时不猜测业务职责。
- 同一轮证据必须来自同一版本；中断、修改和失败后保留旧记录，使用新批次。

## Unity Skills连接与执行规则

本节仅在Blender确认和Unity阶段授权之后执行；提前了解用户提供的Unity版本、管线、导入器和设备信息不等于提前连接工程。

1. 读取执行环境中实际安装的Unity Skills技能说明，按其连接发现规则找到目标服务，不假定固定端口或直接使用其他任务的连接。
2. 通过服务检查健康状态、实际工程路径、版本、操作模式和可用功能范围，核对用户指定工程。多个工程或身份不明确时停止并询问。
3. 核查全项目编译、当前场景未保存状态和其他工作。不能自动丢弃未保存场景或修复无关业务依赖；保存恢复副本须有适当授权。
4. 根据服务返回的真实能力和参数准备操作；不猜技能名。按技能要求先做执行前检查，处理批准请求；不自行扩大权限。
5. 若服务不允许场景创建，解释限制并暂停。不能绕过Unity Skills，改用其他接口、手改场景文件或执行自制脚本来规避限制。
6. 获准操作后重新查询Unity里的实际资源和场景状态；服务回包成功不能代替文件、材质、引用和画面验证。
7. 保留原始错误，连接失败不反复写入，不自动切换到另一个工程。

本工具包未实现Unity连接命令；连接由执行端的Unity Skills负责。这一约定不会改变其本身的授权规则。

## 独立测试场景

导入新资源目录和新测试场景，命名包含任务与版本；保留已有场景，不把测试场景加入正式发布范围。具体目录必须先确认，不能沿用历史案例的业务路径。

场景显式包含：模型根节点、固定相机、可控灯光、必要的尺度参照；需要目标效果时再加入已确认的环境设置。明确关联模型、相机和灯光，不依赖业务启动器或隐式查找。

验证顺序：全部资源可读、材质无缺失 → 中性照明检查 → 目标效果检查 → 用户确认 → 保存并重开。重开若发现差异，撤回相应通过结论并修复；未获重新确认不得交付为已通过。

检查模型尺寸、位置、独立节点、共享数据、贴图、法线、透明和目标导入器支持范围。不要强制将所有项目套用相同UV策略或材质扩展。

视觉、运行性能、目标设备和业务接入分别报告。没有目标设备只写未测；新测试场景通过不意味着正式场景可直接替换。

## 输出和恢复

交付工程、模型、资源、测试场景位置、对比图、已知差异与未测试清单；列清依赖，不单独交付缺少资源的Unity场景。若要跨工程打包，另行确认所需依赖和权限。

按 [执行记录模板](../文档模板/三维场景转换与游戏优化-执行记录模板.md) 保存详细证据，给美术用户的总结仅保留实际结果、注意事项和下一步。正式业务替换、发布、软件安装和破坏性清理均不在默认范围内。
