# 仓库发布与资产管理

本仓库只管理通用工具、文档和测试，不承载场景资产与历史转换输出。Git仓库不是模型备份库，删除本机文件不会因为上传了代码而自动变得可恢复。

## 内容范围

- 提交：已审查的脚本、HTML内容源与生成页、说明、测试、配置样例和Git规则。
- 不提交：.max、.blend、FBX、GLB、纹理素材、客户资料、运行日志、备份、本机配置和凭据。
- 大资产由使用者在其有权限的独立存储中管理。若未来需要公共示例，另行核实素材权限与体积；不默认上传实际项目模型。
- 需要资产清单时记录名称、版本、用途及校验值；私人下载链接、口令和访问密钥不能放入公开仓库。

## 发布检查

1. 查看工作区改动，确认不混入其他任务的内容。
2. 新文件先审查并加入configs/分享白名单.json；配置样例不能包含本机路径。
3. 运行README中的测试和生成一致性检查，再运行分享检查。
4. 显式暂存批准的文件，核对暂存差异、文件数量、大小和文件类型；禁止强制添加被忽略的资产。
5. 正常提交与推送，不强制覆盖远程历史；远程有新改动时先检查，不擅自重置。
6. 从远程重新获取干净副本并复测，区分上传成功与可独立使用。

## 文档生成和换行

六步Markdown是内容源，修改后运行生成器；HTML不单独编辑。.gitattributes统一LF，保证Windows与其他平台检出后，生成结果的字节校验可复现。不要仅删除生成检查来掩盖换行差异。

## Git LFS与其他存储

本仓库首版不启用Git LFS。若确实需要多人维护大模型版本，应先确认资产范围、服务额度和维护方式，再设计独立资产仓库或存储；不把全部过程文件自动加入LFS。

## 许可证和发布权限

当前没有指定开源许可证，不擅自生成授权文本。仓库可见性和许可证选择由维护者决定；公开代码不代表附带商业软件或第三方素材权限。

## 验证边界

离线检查验证配置、规则、生成和模拟交互，不启动三维软件，不替代真实Max审计、Blender回读、浏览器视觉或Unity设备验收。
