# 文档管理规范

适用于本仓库的文档、生成页面和引用它们的代码。维护状态不是模型任务的验收状态。

## 放在哪里

- 使用指南：美术操作、快速开始和通用图示。
- 执行规范：长期流程、边界、环境、分享及发布规则。
- 文档模板：待填写的任务和验收记录，不预先写通过。
- 模块说明：有真实源码的模块职责、参数、限制和验证方式。
- 项目开发经验：问题原因、方法及适用范围。

原模型、客户资料、任务报告和历史备份另行保管，不进入本仓库默认发布范围。不为空目录建立模块说明。

## 入口与唯一依据

README.md介绍能力，docs/README.md导航文档，docs/apps-code-map.md只导航代码与就近说明。六步Markdown是正文依据，HTML由生成器产生，不单独修改正文。

一条长期规则只设一个主要维护位置，其他文档引用；简版和详版明确主次。固定结构的生成源不强行插入会破坏解析的头部。

## 文件命名

有意义的中文名称，词组用连字符，技术名称可保留；无空格或无意义标点。长期指南、规则和模块不在名称中堆日期。需要记录某次变更时使用主题-类型-YYMMDD.md。README.md、AGENTS.md和apps-code-map.md保留约定名称。

## 更新步骤

1. 查现有文档，优先在正确落点更新，不复制一份全文。
2. 新文件登记到configs/分享白名单.json，审核用途、隐私和权限。
3. 功能变化同步代码导航与就近模块说明；有复用价值的问题写入经验。
4. 移动文档时同步相对链接、代码路径和白名单；不要只修导航。
5. 修改六步Markdown后重新生成HTML，运行生成检查、相关测试及分享检查。
6. 提交前检查差异和实际文件清单；未验证的视觉或运行效果明确标注。

## 分享和证据

仓库内链接使用相对路径，可分享文档不包含本机个人路径、访问密钥或客户素材。白名单是分发范围，.gitignore是误提交防线，二者不能替代人工审查。

旧记录不能作为新任务的授权和证据，未做的检查不得写通过。文档中的“当前”和“最新”必须指向明确版本或日期。真实场景的记录按模板另存，不自动提交到公开仓库。

本仓库没有完整场景工程的文档分类数据库或迁移工具，不要求运行未提供的维护脚本。
