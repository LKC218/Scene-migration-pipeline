# 三维场景转换与游戏优化标准流程

版本：2.0。通用入口只实现安全审计；下列完整流程是后续适配和验收规范，不表示所有阶段已自动化。

## 开始使用

面向美术用户的说明与流程图见 [美术操作流程](../使用指南/场景迁移与优化-美术操作流程.md)。执行者另遵循 [Agent执行约定](场景迁移与优化-Agent执行约定.md)：用户确认指定Blender版本且授权Unity阶段、导出回读通过后，才通过Unity Skills连接指定工程。默认只导入独立目录和新建测试场景，不授权业务替换。

先读 [快速开始](../使用指南/快速开始.md)，复制 [执行记录模板](../文档模板/三维场景转换与游戏优化-执行记录模板.md)。核对 [脚本适用范围](脚本适用范围.md)，禁止直接复用案例预算、句柄或固定输出路径。

## 输入与授权契约

| 必填项 | 内容 |
|---|---|
| 输入身份 | 源文件、资源目录、大小、SHA256、冻结副本 |
| 环境 | 实际软件与插件版本、路径、授权可用性、磁盘空间 |
| 目标 | Blender编辑或GLB、目标引擎／管线／设备、灯光／相机／碰撞／LOD范围 |
| 质量与预算 | 唯一几何、实例累计及可见负载口径，关键近景，允许差异 |
| 授权边界 | 是否允许UV修复、近似替代、减面、烘焙、插件操作及引擎写入 |

源文件和高模母版不可覆盖；Safe Scene 不可关闭；不得为完成转换擅自购买、安装、迁移插件或改变原外观。软件类可创建不代表渲染授权已通过。

## 阶段一：输入冻结与环境检查

核实源资产来源及安全性；建议复制场景与关联资源到独立输入目录并核对哈希。确认工作盘能容纳母版、副本、中间文件、日志和回退备份，不只计算最终文件。

通用入口不自动冻结输入，只保护源父目录和显式 protect 目录，实际审计前后核对哈希。用户仍在编辑的资产不能作为稳定基线；新输入版本使用新批次。

输出：输入身份、保护清单、环境记录、授权、回退位置。通过条件：身份与范围清楚，环境可用，已有文件不受覆盖。check 只做静态检查，不能替代插件实际加载验证。

## 阶段二：安全审计与依赖决策

使用独立 Max Batch 和 Safe Scene，读取基础结构、插件类、资源与原始材质参数，保留日志。详情中的 read_error、not_lossless 和 partial 不可忽略。

| 发现 | 必须处理 |
|---|---|
| 缺失插件或有效图片 | 补齐并复核，或就具体替代范围取得授权 |
| 唯一同名资源候选 | 标记待重链接，不宣称已经恢复 |
| 显式禁用或零贡献引用 | 保留证据，不能用一个禁用路径掩盖其他有效路径 |
| 多材质对象 | 进一步核对面材质编号，不将绑定数当作受损对象数 |
| 未找到引用路径 | 继续核查环境、修改器和编辑器引用，不直接删除资源 |
| 参数读取失败 | 标记部分提取，明确对后续映射的影响 |

输出：审计、参数快照、缺失清单和下一阶段建议。无阻塞仅表示需要继续评估映射，绝不表示完成转换。

## 阶段三：材质小样与Blender迁移

先验证代表性材质、UV、多材质槽、实例、单位、负缩放、层级和相机，再扩大到全场景。通过中间几何与JSON清单解耦软件，记录句柄和对象归属；句柄不作为跨项目唯一身份。

区分直接PBR映射、二维UV通道采样、参考平面法线采样与对象级高低模烘焙。视角相关、双面不同材质、多UV或几何相关效果不能默认用一张平面贴图无损表达。

受控近似必须有范围、来源和差异说明；不以统一材质或调整曝光隐藏错误。源文件不改，工作副本保存后必须重新打开检查图片打包与引用。

输出：小样、材质映射表、差异、独立工程。通过条件：约定的小样和回读检查通过；未验证的效果保持待验收。

## 阶段四：游戏优化与材质适配

先测几何、图片和实例的实际负载，再选择减面、共享或贴图处理。文件大小、显存、渲染开销是不同指标，不用单一体积指标代替性能。

- 保留独立节点和共享数据，避免为“单文件”合并整个场景。
- 对重要近景、文字、细长结构和法线图制定单独预算。
- 命名和原名映射分开保存，不能因同名合并不同材质。
- 保留可回退母版；超预算则说明获准例外，不改变统计口径。
- 材质效果必须考虑目标导入器对UV、扩展、透明、透射和法线的支持。

输出：优化副本、统计、映射、小样对比与近景证据。通过条件：预算、几何和视觉满足约定，或具体例外获准。

## 阶段五：GLB回读与目标验收

按明确集合导出，排除不交付的辅助物。先验证基础格式，再考虑压缩；格式合法不代表材质正确。

在新进程或空白场景回读，检查节点、索引、内嵌图片、材质、法线、尺度和真实渲染。glTF按UV、材质和法线边界拆顶点，不能直接比较控制网格顶点数。

目标引擎与设备分别验证导入、层级、全部材质、固定视角和实测帧时间；没有目标环境就写“未执行”。场景隔离截图必须确认确实是目标资产，而不是别的模型。

输出：工程、GLB、资源、对照图、报告、哈希清单。通过条件：本任务约定层级均完成，未完成项和例外明确。

## 证据与状态

每次尝试记录输入哈希、工具版本、实际参数、起止时间、耗时、退出码、日志、输出哈希、警告和下一步。耗时使用系统绝对时间差。

| 状态 | 含义 |
|---|---|
| 阻塞 | 缺少数据、授权、安全前提或检查失败 |
| 已生成待验证 | 文件存在，但回读或视觉未完成 |
| 结构通过含源警告 | 本轮结构通过，保留源问题 |
| 候选版 | 可继续验证，但约定验收仍未完成 |
| 已验收 | 本任务全部验收完成，例外明确接受 |

批次目录位置不代表验收等级。静态检查、真实审计、工程回读、视觉、引擎及设备必须分别声明。

## 失败处理与续跑

输入变化时停止混用证据；非零退出码必须结合日志分析，不因产物存在而放行。超时或中断不代表子进程已经停止，先核查再决定新批次，禁止盲目重复启动。

工具错误与源资产错误分开记录。保留首次失败，不删除历史证据，也不修改源工程来让检查通过。改变转换器、参数或材质表达后，重做受影响的下游检查。

## 文档维护

流程维护跨项目规则；模块说明维护接口与限制；案例报告记录执行证据；代码导航只写职责与文档落点。实际任务的历史证据由使用者另行保存，不进入本仓库，不代替本轮验收。
