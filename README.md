# Scene Migration Pipeline · 场景迁移协作工具

为美术人员与 Agent 提供 .max 场景安全审计、Blender 迁移优化和 Unity 导入测试的协作流程。

**当前可直接执行的通用功能是 Max 安全审计。** Blender 材质迁移、减面和 Unity 适配仍需根据具体场景制定方案；本仓库不是任意场景的一键无损转换器。

## 美术人员：从六步指南开始

下载仓库后，用浏览器打开 [六步可视化指南](docs/使用指南/场景迁移与优化-六步指南.html)，把同目录的 [Markdown](docs/使用指南/场景迁移与优化-六步指南.md) 交给 Agent。HTML 可离线阅读，无需启动网站服务。

准备素材 → 检查与备份 → Blender迁移优化 → 确认Blender效果 → Unity导入测试 → 确认交付。

页面一次只显示一步；切步和复制只辅助阅读，不控制三维软件，也不代表任务授权。您只需提供素材和要求、查看对比图、确认效果，无需写代码或执行命令。

可以直接对 Agent 说：

> 请阅读六步指南和 AGENTS.md，检查我的场景与配套素材，先提出处理方案。保留原文件；Blender 指定版本经我确认、导出检查通过并获准后，才通过 Unity Skills 连接指定工程，新建测试场景，不修改正式场景。

## Agent：检查与执行

参与多人开发前，先获取远程并执行协作初始化；详见 [多人协作与提交规范](docs/执行规范/多人协作与提交规范.md)。每人使用独立克隆和工作分支，禁止直接推送main。新路径先单独审核仓库白名单，再提交文件；下载ZIP阅读指南不需要安装Git钩子。

基础入口需要 Windows、Python 3.10+，仅使用标准库。真实审计另需可用的 3ds Max；Blender 和 Unity Skills 是后续阶段的外部环境，不随仓库安装。

1. 读取 [快速开始](docs/使用指南/快速开始.md)、[环境与配置](docs/执行规范/环境与配置.md)。
2. 将 `configs/项目配置.example.json` 复制为 `configs/项目配置.local.json`，填写使用者自己的路径。空白样例会阻塞，不会寻找旧场景。
3. 执行检查与预览，不启动三维软件：

```powershell
python -X utf8 -B scripts/通用/项目入口.py check
python -X utf8 -B scripts/通用/项目入口.py plan
```

4. 获得本任务明确授权后，才运行 `audit --execute`。固定使用 Safe Scene，不保存源 .max，不自动安装插件，不连接 Unity。

## 验证，不启动三维软件

```powershell
python -X utf8 -B scripts/验证/测试通用入口.py
python -X utf8 -B scripts/验证/测试独立审计.py
python -X utf8 -B scripts/验证/测试材质依赖.py
python -X utf8 -B scripts/验证/测试六步指南.py
python -X utf8 -B scripts/通用/生成六步指南.py --check
python -X utf8 -B scripts/通用/分享工具包.py check
```

维护者可另用 Node.js 标准库执行 `node scripts/验证/测试六步页面交互.cjs`。这是模拟交互测试，不是真实浏览器或视觉验收。测试链接创建受系统权限限制时会明确跳过。

完整Git克隆另运行 `python -X utf8 -B scripts/验证/测试提交检查.py` 检查协作防护；该测试、Git钩子与协作脚本不包含在阅读分享包中。

六步正文只修改Markdown，再运行 `python -X utf8 -B scripts/通用/生成六步指南.py` 更新HTML。换行统一为LF，避免不同系统下载后的一致性检查误报。

## 仓库与大资产分开

只提交通用代码、配置样例、指南和测试。模型、贴图、源工程、转换结果、日志、备份及本机配置不进入仓库；需要时由使用者另行提供。克隆仓库不等于取得某个案例的完整模型。

未来新增文件须先审核用途、依赖和权限，再由维护者批准 `configs/仓库提交白名单.json` 的扩展；只有需要进入分享包的内容才加入 `configs/分享白名单.json`。二者用途不同，不要直接将整个工作目录上传。

## 能力与使用边界

- 不覆盖原件和既有交付，不默认减面、替换材质或迁移插件。
- 审计成功不等于迁移、画面或目标设备性能已通过。
- Unity测试必须另具备Unity Skills，核对目标工程并遵守批准范围。
- 未测试的版本、资产和设备保持未验证。
- 仓库未指定开源许可证；未附带商业软件、第三方插件或客户素材，不为它们提供使用授权。
